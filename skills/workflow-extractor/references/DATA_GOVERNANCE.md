# 数据治理类工作的扩展要求

**加载条件**：提炼的工作涉及数据清洗、转换、标准化、整合、QC、导出或发布时启用。
纯代码工具、应用运行类工作不需要本节。

## 数据治理的典型可沉淀流程

识别候选流程时，优先考虑以下类型：

- 新批次数据的标准化接入
- 模态特异性的清洗与格式转换
- Schema 与语义标准化
- 个体、样本、检测及纵向事件的关联
- 数据质量评估与异常检测
- 治理结果的验证与发布
- 常见错误的诊断与修复

仍需满足 SKILL.md 第 5 步的通用筛选条件。

启用后，生成的 SKILL.md 在通用章节之外，额外增加
**Data Contract** 与 **Validation & Quality Gates** 两节。

## 输入还原

按本 skill 的 `references/INPUT_CONTRACT.md` 通用模板填写。数据治理需特别写清：

- 多模态数据的组织方式（按年份 / 按模态 / 分层目录）
- 个体、样本、检测、事件等标识及其关系
- 编码体系与元数据标准（单位、术语、版本）
- 多批次输入之间的差异

当新批次输入出现偏差时，先依据这些记录尝试适配（列名映射、格式转换、
单位统一、字段处理）；无法确定语义时停止并询问。

## Data Contract（SKILL.md 章节）

- 输出 schema 与字段语义
- ID 映射及纵向事件关联规则
- 单位、编码体系、术语及版本
- 数据来源、处理版本及 lineage
- 与现有数据模型和治理规范的衔接

**必须先核对项目已有约定，不得自创与当前系统冲突的规范。**

## Validation & Quality Gates（SKILL.md 章节）

- 输入合法性检查
- 清洗前后的数据量、缺失率、重复率及异常统计
- 主键唯一性、关联完整性、时间和数值合理性
- 标准映射覆盖率与未映射项
- 成功标准、失败条件及异常隔离策略
- 需要停止执行并请求人工确认的情况

**不得编造质量阈值。** 阈值必须来自已有文档、配置、历史产物或负责人确认；
来源不明时标注为待确认，不要固化为自动判断。

## 安全要求

- 默认只读检查或 dry-run
- 不覆盖原始数据，不擅自修改或删除现有数据资产
- 未经授权不执行生产发布、远程推送等操作
- 不把个人健康信息、身份信息、凭证、敏感路径写入 skill 包
- 优先使用合成数据、脱敏样例或 schema 级测试进行验证

## 数据治理额外的停止条件

通用停止条件见 `QUALITY.md`；数据治理还需在以下情况停止：

- 需要连接生产系统或使用真实个人信息
- 标准映射覆盖率低于既有要求且原因不明
- 主键/关联键冲突影响个体归属或纵向关联
- 跨模态合并时标识体系不一致
