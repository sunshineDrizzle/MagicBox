# 输入形式契约（模板）

生成 skill 包时，若输入形式较复杂，复制本模板为包内的
`references/INPUT_CONTRACT.md` 并填写。简单工作流可直接把要点写进
SKILL.md 的 Inputs 章节。

**不要把「表格」当作默认输入形态。** 先判断形态，再按对应类型记录。

## 1. 执行入口如何获取输入（通用）

这是输入形式的**权威来源**。记录：

- 取数方式：命令行参数 / 配置文件 / 环境变量 / 固定路径 / stdin /
  目录扫描 / 网络请求 / 人工填写
- 入口签名与调用示例
- 入口自己做了哪些校验；输入缺失或不符合要求时如何报错

无真实样本时先推断候选路径（见 SKILL.md 第 4 步），只读抽样，不写入包内；
契约始终以执行入口和代码为主，样本仅用于验证与补充。

## 2. 判断输入形态

| 形态 | 典型输入 | 重点记录 |
|---|---|---|
| 文件集合 | 数据文件、文档、图片、音视频 | 格式、目录组织、命名、编码、大小 |
| 表格/结构化数据 | csv/xlsx/parquet/数据库表 | schema、字段语义、单位、主键、缺失与重复 |
| 代码与构建 | 源码树、依赖清单、构建配置 | 版本、依赖锁定、构建命令、产物 |
| 服务/API | endpoint、请求体、认证 | 协议、请求/响应 schema、鉴权、限流、超时 |
| 配置与环境 | 配置文件、环境变量、密钥 | 必填项、默认值、敏感信息 |
| 消息/事件 | 队列消息、日志流、事件 | 格式、顺序、幂等、去重 |
| 人工输入 | 表单、判断、口头指令 | 字段、校验规则、确认点 |
| 混合 | 以上多种 | 分别说明，标注依赖顺序 |

## 3. 输入契约（按形态填写，不必填满）

### 3.1 通用

- 来源：哪个系统 / 由谁提供 / 如何获取
- 规模：文件数、数据量、时间范围
- 命名与组织约定
- 编码/字符集/时区
- 版本与兼容性
- 参数默认值遵循 SKILL.md 第 6 步的三分类：环境无关可给默认值，
  环境相关用 `null`/占位符，依赖单独列表（必需性 / 兼容范围 / 实测版本）

### 3.2 若为表格/结构化数据

- schema 与字段语义、单位
- 主键与关联键
- 缺失、重复、异常值的定义
- 正常与异常样例

### 3.3 若为代码/构建

- 语言与版本、依赖清单与锁定文件
- 构建/安装命令
- 运行环境与权限
- 产物位置

### 3.4 若为服务/API

- endpoint 与协议
- 请求/响应 schema 与示例
- 鉴权方式与凭据来源
- 限流、超时、重试约束

### 3.5 若为人工输入

- 需要人提供哪些信息
- 格式与校验规则
- 哪些判断不能自动化

## 4. 前置检查

可直接执行的检查命令或脚本（按形态给出）：

```bash
# 示例：文件/数据类
python scripts/check_input.py --input <path>

# 示例：服务类
curl -sf <endpoint>/health
```

检查项（按形态选择）：

- 文件/数据：必需文件或字段是否存在；数量/行数、缺失率、重复率
- 代码：依赖是否可解析、构建是否可执行
- 服务：连通性、鉴权、响应结构
- 配置：必填项是否齐全、敏感值是否已注入
- 人工：输入是否完整、是否满足格式

## 5. 偏差适配规则

| 偏差 | 处理方式 | 可自动？ |
|---|---|---|
| 命名/字段同义词不同 | 映射到标准名称 | 是 |
| 格式不同（日期、编码、容器） | 统一转换 | 是 |
| 单位不同 | 换算 | 是 |
| 缺少非必需项 | 留空或按默认值 | 是 |
| 缺少必需项 | **停止并询问** | 否 |
| 语义不明（新编码、新类别、新结构） | 记录并询问 | 否 |
| 输入形态变化（如新增 API 输入） | **停止，请用户确认是否扩展契约** | 否 |

原则：**能确定语义的偏差可自动适配；语义不明的必须停止询问。**
每次自动适配都要在输出或日志中记录。

## 6. 调用示例

```bash
<执行入口> <最小输入示例>
```

输入不满足契约时，先报告缺什么、尝试了哪些适配，再决定是否继续。
