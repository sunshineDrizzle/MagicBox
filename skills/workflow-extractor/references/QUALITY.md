# 易错信号与类型化要求

完成标准见 SKILL.md 第 7 步的验证重点与自检清单；本文件补充易错信号和按类型的选择。

## Red flags

出现以下情况时停下重新审视：

- skill 读起来像原项目 README 的改写
- 没有 driver，只有文字说明
- Troubleshooting 全是通用建议，没有真实错误
- 声明「某平台不支持」但没有实际尝试
- 所有步骤一次就成功，且没有运行证据
- 只在原工作路径中验证，未做隔离测试
- 用「沿用上次决定」代替本次交互确认
- 没有三项交互门的决策记录就进入构建
- 产出包含真实数据、个人标识、凭据或内网地址

## driver 形态（按工作类型）

| 工作类型 | driver |
|---|---|
| 数据处理管线 | `run.sh` / `pipeline.py --input --output` |
| 查询/分析 | `queries/*.sql` + 执行脚本 |
| 服务/应用 | 启动脚本 + 探测脚本 |
| CLI 工具 | 代表性参数的 smoke 脚本 |
| 手工流程 | 分步 checklist + 每步校验命令 |
| 无法脚本化 | 人工步骤 + 产物校验，明确标注「需人工」 |

## agent 决策 vs 确定性代码

- **确定性代码**：重复性强、需要严格保证正确性的步骤
- **agent**：流程编排、参数选择、异常诊断、必要的人工交互
- 不得把尚未明确的业务规则固化为自动决策

## 必须停止并请求人工确认

- 源数据与文档冲突，且无法用代码/日志裁决
- 需要覆盖或删除原始数据
- 需要生产发布、远程推送或外部写入
- 质量指标低于既有阈值，但阈值来源不明
- 出现无法归类的异常

## 可选：机器可读输出

若工作流会被流水线或其他 agent 调用，建议提供 `--json` 或等价的结构化输出，
至少包含：状态、产物路径、关键计数、验证级别。
