# 证据源探测与使用

## 会话历史：按执行 agent 自己的格式探测

不要硬编码某一种 agent 的路径。先判断「当前是谁在执行」，再探测它自己的历史目录。

| agent | 常见位置（示例，以实际版本为准） |
|---|---|
| Claude Code | `~/.claude/projects/<路径编码>/<sessionId>.jsonl`；`~/.claude/history.jsonl` 含 `project` 字段 |
| Codex | `~/.codex/sessions/`（JSONL，按日期分目录） |
| 其他 | 优先查该 agent 的文档/配置；再查工作路径下的 `logs/`、`.history/`、`.agent/`、`.sessions/` |

Claude Code 的路径编码：`/home/u/proj` → `-home-u-proj`（`/` 替换为 `-`）。
编码有歧义时，用 `history.jsonl` 的 `project` 字段精确定位，或反向匹配目录。

探测结果只有三种：**可用**（给出路径、大小、时间范围）、**不可用**（不存在/无权限）、
**部分可用**（有记录但格式无法解析）。后两种都要在报告中写明。

## 其他历史上下文

除会话记录外，还应探测：

- **任务摘要**：agent 的任务/摘要记录（位置因平台而异）
- **持久化 memory**：如 Claude Code 的 `~/.claude/projects/<路径编码>/memory/`
- **版本历史**：commit、PR、Issue、变更记录（若项目使用版本控制）
- **已有 skill、SOP、操作规范**

这些同样只取元数据，按预算决定是否纳入；不可访问时在报告中写明缺口，
并用可验证的代码、配置、文档或日志作为替代证据。

证据分级见 SKILL.md 第 4 步。

## 读取会话的正确顺序

1. **先有目标，再筛证据**：从文档/代码/用户描述确定工作目标后，再按目标筛选
2. 只取轻量元数据：文件数、大小、行数、时间范围、会话数量
3. 按 SKILL.md 第 3 步的阈值判断是否需要让用户决策
4. 用户选择：全部纳入 / 筛选后纳入 / 不纳入；**默认不纳入**
5. 纳入时按条件筛选，并执行预算

本文件只说明如何探测与筛选。

### 筛选条件

- 时间窗（与工作时间吻合）
- 关键词（项目名、脚本名、数据名、产物名）
- 角色（只取 user/assistant 消息，跳过工具原始输出）
- 涉及的文件路径 / 命令

会话记录常包含与当前工作无关的内容。**不要因为"看到了"就纳入证据。**

## 冲突处理

- 文档说 A、代码做 B：**执行细节以代码为准，意图以文档为准**，并记录差异
- 文档比代码新 / 旧：标注版本与时间，不自行判断谁对
- 日志行为与文档不符：以日志为准，记录为「实际行为」
- 任何无法裁决的冲突：写入 A–F 报告的 E 项，交用户确认

**禁止**为了让流程"看起来完整"而编造规则、阈值、参数或步骤。

## 敏感信息

会话与日志可能包含个人健康信息、身份信息、凭证、内网路径。提炼前：

- 不把原始敏感值写入 skill 包
- 用占位符或脱敏示例
- 只保留与工作流有关的结构信息
