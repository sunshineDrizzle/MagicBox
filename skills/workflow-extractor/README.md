# workflow-extractor

> **这是给人看的简要说明。agent 不需要读这个文件。**
> agent 执行时以 `SKILL.md` 为准；本文件不构成运行契约。

## 它做什么

把**已经发生的工作**（代码、文档、日志、会话、产物）提炼成一份**独立自洽、可复用**的 Agent Skill 包，让其他 agent 能按同一流程完成同类工作。

它不是「凭空设计流程」，而是还原真实做过的事，并补齐可执行入口、输入契约、完成信号和异常处理。

## 什么时候用

- 有一套反复执行的工作，想沉淀成 skill
- 想让 Codex、Trae、WorkBuddy 等其他 agent 也能复用这套流程
- 想从历史代码、文档、日志中总结出可执行的工作流

## 怎么用

对你的 agent 说：

```text
把这套工作提炼成 skill，工作路径是 /path/to/work1 和 /path/to/work2
```

如果你的 agent 支持 skill 自动加载，也可以直接用它的 skill 调用方式；
不支持时，把 `SKILL.md` 交给 agent 按其中的流程执行即可。

## 你会得到什么

一个自包含的 skill 包：

```text
<skill-name>/
├── SKILL.md          # agent 执行契约
├── README.md         # 默认生成，面向人
├── scripts/          # 可执行入口（driver）
├── references/       # 数据契约、异常处理、证据索引
└── assets/           # 按需：脱敏样例、模板、schema
```

技能包实际执行后，输出目录还会生成 `run_manifest.json`，记录本次使用的输入、输出、参数、依赖实测版本和结果。

外加一份 A–F 交付报告：已有工作回顾、Skill 交付、复用收益、验证结果、遗留问题、下一步建议。

## 几个重要行为

- **证据优先**：只写有证据支持的内容，推测会显式标注
- **复用而非重写**：优先调用已有脚本和工具；复制进包是为了自洽，不是为了改造
- **独立自洽**：删掉原工作路径后，skill 包仍能凭外部输入运行
- **强制交互门**：每次执行都会向你确认三件事——工作路径、超阈值证据是否纳入、输入样本路径；不会复用历史决定
- **参数前置**：产出包的 driver 支持 `--config` / `--yes` / `--dry-run`，启动时打印配置摘要；免交互只跳过常规确认，异常仍会中断
- **依赖不过度约束**：区分必需性、兼容范围、实测版本；实测版本不作为硬要求
- **默认只读**：全量执行、覆盖产物、外部写入都需要你授权
- **敏感信息**：产出包不含真实数据、凭据、内网地址；样例一律脱敏或合成

## 不适用

- 一次性探索或尚未验证的工作
- 需要修改源数据的场景
- 没有执行入口、只能靠人反复口头判断的流程（可以先沉淀成清单，但价值有限）

## 文件结构

```text
workflow-extractor/
├── SKILL.md                  # agent 执行契约：8 步 + 自检
├── README.md                 # 本文件：面向人的简要说明
└── references/
    ├── EVIDENCE.md           # 证据探测与预算
    ├── QUALITY.md            # 易错信号与完成标准
    ├── DATA_GOVERNANCE.md    # 数据治理扩展（条件加载）
    └── INPUT_CONTRACT.md     # 输入形式契约模板
```

## 进一步阅读

- **agent 执行**：读 `SKILL.md`
- **证据怎么取、预算怎么控**：`references/EVIDENCE.md`
- **什么算做完、哪些信号说明做错了**：`references/QUALITY.md`
- **数据治理类工作的额外要求**：`references/DATA_GOVERNANCE.md`
- **输入形态怎么记录**：`references/INPUT_CONTRACT.md`
